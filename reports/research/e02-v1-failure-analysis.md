# E02 v1 Supplemental Failure Analysis

**Classification:** append-only software-qualification failure analysis

**Attempt:** E02 v1

**Scientific disposition:** not tested

## Result

The first E02 qualification attempt failed during collection. It did not complete
restore, probe evaluation, or final export, and it produced no behavioral finding.
The retained database contains 465 committed turns (indices 0–464), 930 delivered
adapter-entry observations, three checkpoint manifests, and zero completed probe
reports. Only the first of five planned slots was attempted.

The terminal event was the registered Gateway safety pause after five consecutive
timeout rejections. The collector subsequently tried to continue the paused run and
raised `RunNotAcceptingTurnsError`. The assertion recorded in the tracked terminal
receipt wrapped that collector failure; it was not the initiating event.

## Causal diagnosis and correction boundary

A development-only reproduction found that normalized adapter calls and the outer
runtime used the same 1,000 ms deadline. The outer timer was armed first, while the
adapter intentionally held a completed response until that boundary. Policy
synchronization then occurred outside the normalized interval. This created a race
in which an on-schedule normalized response could be classified as late.

The correction gives a normalized adapter one deadline authority for remote work,
parsing, policy synchronization, and fixed-schedule release. The runtime continues
to enforce its deadline for adapters that do not own that authority. Genuine late
responses still fail, and the five-rejection safety pause remains enabled. A fresh
development smoke recorded ten turns with no timeout reason codes; it is a software
observation, not a substitute for a newly registered E02 qualification.

## Preserved evidence and verification

The original registration packet, activation binding, terminal receipt, raw slot
summary, partial SQLite database, and log remain unchanged. Their byte sizes and
SHA-256 digests are recorded in
`reports/research/e02-v1-failure-evidence.json`. The portable audit verifies tracked
artifacts and the interpretation:

```sh
corepack pnpm audit:e02-failure
```

Where the separately retained ignored evidence directory is available, the live
audit additionally verifies each raw-file digest, database table counts, the exact
safety event, slot accounting, and the absence of restore and probe reports:

```sh
corepack pnpm audit:e02-failure:live
```

No original artifact is repaired or regenerated by either command. A future E02
attempt must use a prospectively registered packet, new run identifiers, and a new
seed namespace.

## Claim boundary

This analysis establishes the recorded failure sequence and a bounded software
diagnosis. It does not establish E02 qualification, observation-leakage bounds,
language emergence, a negative scientific result, independent review, or a public
timestamp.
